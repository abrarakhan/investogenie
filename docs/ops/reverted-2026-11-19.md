# Revert of 2026-11-19 — what was reverted and how to bring any of it back

On 2026-11-19 production was returned to the code and configuration of **Monday
2026-11-16 17:00 IST** (tree of `59c324f`) because screens stopped loading and no
cause could be isolated to one change.

Nothing was deleted. The full pre-revert code is preserved at:

- branch `backup/pre-revert-2026-11-19` (origin)
- tag `backup-pre-revert-2026-11-19` (origin), both at `5677126`

## Kept deliberately (not reverted)

- `AGENTS.md` — the validation contract was a separate explicit request.
- `db/migrations/0084`, `0085`, `0086` — already applied in production. They are
  additive (new table, new nullable columns) and ignored by the older code.
  Removing deployed migration files would rewrite deployed history.

git cherry-pick <hash>          # from the list below; the backup branch has every commit

## Host configuration that was reverted (production, Wed 2026-11-18)

Re-apply with the commands shown. Values are not secret.

| Setting | Was set to | Reverted to | Re-apply |
|---|---|---|---|
| PostgreSQL `shared_buffers` | 768MB (`/etc/postgresql/16/main/conf.d/10-investogenie-tuning.conf`) | default (128MB) | write `shared_buffers = 768MB` to that file, `sudo systemctl restart postgresql`, then restart both app services |
| Role `investogenie` `random_page_cost` | 1.1 | default (4) | `alter role investogenie set random_page_cost = 1.1;` |
| `/etc/investogenie/investogenie.env` `PYTHON_ENGINE_TIMEOUT_MS` | 180000 | removed (code default 30s) | add the line, restart `investogenie` |
| `/etc/investogenie/investogenie.env` `PG_DISPLAY_STATEMENT_TIMEOUT_MS` | 150000 | removed | add the line; only read by the reverted `lib/db.ts` |

Measured before the revert, same 537,634-row query under the same load:
`random_page_cost` 4 took 79.5 s warm and 120.7 s cold; 1.1 took 19.9 s warm and
52.6 s cold. Reverting it brings the slower plan back.

A copy of the pre-revert host files is kept on the server in
`/root/investogenie-config-backup-20261119/`.
